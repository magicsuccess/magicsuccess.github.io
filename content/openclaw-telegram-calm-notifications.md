# ออกแบบระบบแจ้งเตือนที่ไม่รบกวน: คู่มือ OpenClaw + Telegram แบบ 3 ระดับ

ระบบอัตโนมัติที่ส่งทุกเรื่องอาจดูเก่งในวันแรก แต่ไม่นานผู้ใช้จะเริ่มปิดเสียง เพราะข้อความสำคัญถูกฝังในรายงานปกติ เป้าหมายที่ดีกว่าคือ “แจ้งเท่าที่จำเป็น และบอกว่าต้องทำอะไรต่อ” เราจึงจะออกแบบระบบแจ้งเตือนสามระดับสำหรับ OpenClaw และ Telegram จากกติกาบนกระดาษ

## โจทย์จริง: เจ้าของงานมีเวลาอ่านวันละสองรอบ

สมมติว่าเจ้าของธุรกิจใช้ OpenClaw สรุปงาน ตรวจเว็บไซต์ และเตือนเรื่องที่รออนุมัติ เขาเปิด Telegram ช่วง 09:00 และ 18:00 ไม่ต้องการข้อความหลัง 21:00 เว้นแต่เว็บไซต์ใช้ไม่ได้ และทุกการส่งอีเมลหรือเผยแพร่ต้องรอมนุษย์อนุมัติ

ถ้าตั้งให้ทุกเหตุการณ์ส่งทันที ระบบจะรบกวนเกินไป แต่ถ้ารวมทุกอย่างไว้ในรายงานเย็น เหตุขัดข้องสำคัญอาจถูกพบช้า วิธีแก้คือแบ่งตาม “ผลกระทบและเวลาที่ต้องตอบ” ไม่ใช่แบ่งตามชื่อเครื่องมือ

## สามระดับที่ตัดสินใจได้ทันที

ระดับ 1 — ข้อมูลเพื่อทราบ: งานสำเร็จตามปกติ สถิติทั่วไป หรือรายการที่ยังไม่ต้องตัดสินใจ ให้รวมเป็น Digest ส่งตามเวลาคงที่วันละหนึ่งหรือสองครั้ง ข้อความควรสั้นและมีลิงก์หรือรหัสอ้างอิงเมื่อจำเป็น

ระดับ 2 — ต้องดำเนินการ: งานติดขัด รออนุมัติ หรือมีเส้นตายภายในวันนั้น ส่งทันทีในช่วงเวลาทำงาน พร้อมระบุเจ้าของงาน ทางเลือก และกำหนดตอบ ห้ามใช้คำกว้างอย่าง “มีปัญหา” โดยไม่บอกผลกระทบ

ระดับ 3 — เร่งด่วน: บริการหลักหยุดทำงาน ความปลอดภัยเสี่ยง หรือความเสียหายกำลังขยาย ส่งทันทีแม้อยู่นอกช่วงปกติ โดยมีเงื่อนไขเข้มและป้องกันการส่งซ้ำ หากเกิดทุกวัน แปลว่ากติกาหรือระบบต้นทางยังต้องแก้

## เครื่องมือคัดลอกใช้ได้: Notification Contract

คัดลอกแบบฟอร์มนี้ไปกรอกก่อนสร้าง Automation หนึ่งรายการ

ชื่อเหตุการณ์: [ระบุเหตุการณ์เดียว]
ระดับ: [1 ข้อมูล / 2 ต้องดำเนินการ / 3 เร่งด่วน]
เงื่อนไขเริ่ม: [หลักฐานที่ตรวจได้]
ผู้รับผิดชอบ: [ชื่อบทบาท ไม่จำเป็นต้องเป็นชื่อบุคคล]
เวลาที่ต้องตอบ: [ไม่ต้องตอบ / ภายในกี่ชั่วโมง]
Quiet Hours: [ช่วงห้ามรบกวน และข้อยกเว้น]
ช่องทาง: [DM / กลุ่ม / Topic]
ข้อความต้องมี: [เกิดอะไร / ผลกระทบ / ต้องทำอะไร / เส้นตาย]
กุญแจกันซ้ำ: [event-id หรือ incident-id]
การยกระดับ: [เมื่อไรจึงขยับระดับ]
การปิดเหตุ: [หลักฐานว่าแก้แล้ว]

กติกานี้ทำให้ทุกคนเข้าใจคำว่า “ด่วน” ตรงกัน เปลี่ยนเงื่อนไขแบบ “เมื่อดูน่ากังวล” เป็นหลักฐานที่ตรวจได้ เช่น “การตรวจสุขภาพล้มเหลวต่อเนื่องสามครั้ง” ตัวเลขนี้เป็นสมมติฐาน ต้องปรับตามความเสี่ยงจริง

## Prompt สำหรับให้ AI จัดรูปข้อความ

คุณเป็นผู้ช่วยจัดรูปการแจ้งเตือน ห้ามเพิ่มข้อเท็จจริงที่ไม่มีใน Input
สร้างข้อความ Telegram ภาษาไทยไม่เกิน 6 บรรทัด โดยเรียงดังนี้:
1) สถานะและระดับ
2) สิ่งที่เกิดขึ้น
3) ผลกระทบที่ยืนยันแล้ว
4) สิ่งที่ผู้รับต้องทำ
5) กำหนดเวลา
6) รหัสอ้างอิง
ถ้าข้อมูลใดไม่มี ให้เขียน “ยังไม่ยืนยัน” ห้ามเดา

Input ตัวอย่าง:
ระดับ=2, เหตุการณ์=บทความสร้างเสร็จแต่ Quality Gate ไม่ผ่าน, ผลกระทบ=ยังเผยแพร่ไม่ได้, การกระทำ=ตรวจลิงก์อ้างอิง 2 จุด, กำหนด=ก่อน 18:00, รหัส=ART-20260809-01

Output ตัวอย่าง:
[ระดับ 2 · ต้องดำเนินการ]
บทความสร้างเสร็จ แต่ Quality Gate ยังไม่ผ่าน
ผลกระทบ: ยังเผยแพร่ไม่ได้
กรุณาตรวจลิงก์อ้างอิง 2 จุด
กำหนด: ก่อน 18:00 · รหัส ART-20260809-01

## วาง Automation ให้ปลอดภัยและไม่ส่งซ้ำ

เอกสาร OpenClaw ระบุว่า Automations ทำงานใน Gateway รองรับตารางครั้งเดียว ช่วงคงที่ และ cron expression พร้อมเขตเวลา งานรายวันจึงควรระบุ Asia/Bangkok รวมทั้งกำหนด timeout และตรวจประวัติการรัน

สร้างกุญแจกันซ้ำจากประเภทเหตุการณ์กับรอบเวลา เช่น website-down:2026-08-09T11 แล้วบันทึกว่าเคยแจ้งหรือยัง เมื่อเหตุไม่เปลี่ยนไม่ต้องส่งทุกนาที ให้แจ้งอีกครั้งเมื่อยกระดับหรือเมื่อปิดเหตุ หลักนี้เรียกว่า idempotency

OpenClaw แนะนำให้จำกัดผู้ใช้ Telegram ด้วย pairing หรือ allowlist ส่วน Telegram รองรับการรับข้อมูลผ่าน long polling หรือ webhook อย่างใดอย่างหนึ่ง ระบบส่วนตัวควรระบุผู้รับ เก็บ token นอกเนื้อหาและ log อ่านต่อที่ [เชื่อม Telegram กับ OpenClaw อย่างปลอดภัย](/articles/telegram-openclaw-connection/) และ [OpenClaw ขั้นกลาง](/articles/openclaw-intermediate-workflows/)

## Checklist ก่อนเปิดใช้งานจริง

□ จำลองเหตุปกติ เหตุต้องอนุมัติ และเหตุเร่งด่วนอย่างละหนึ่งครั้ง
□ ทดสอบ Quiet Hours และเขตเวลา รวมถึงกรณีข้ามวัน
□ ยิงเหตุการณ์เดิมซ้ำเพื่อดูว่าระบบกันข้อความซ้ำได้จริง
□ ปิดแหล่งข้อมูลจำลอง เพื่อยืนยันว่าระบบรายงาน “ข้อมูลไม่พร้อม” แทนการเดา
□ ตรวจว่าผู้รับที่ไม่อยู่ใน allowlist สั่งงานไม่ได้
□ ตรวจว่า token และข้อมูลลับไม่ปรากฏในข้อความหรือประวัติการทำงาน
□ กำหนดผู้มีสิทธิ์อนุมัติการส่งอีเมล การเผยแพร่ การลบ และการแก้ config
□ ทบทวนคำตอบ AI ด้วย [ระบบ Quality Gate 3 ชั้น](/articles/ai-output-quality-gate/) ก่อนนำไปทำงานที่มีผลภายนอก

## ข้อควรระวังและข้อจำกัด

ระบบแจ้งเตือนไม่ได้แทนระบบเฝ้าระวังเฉพาะทาง และ Telegram ไม่ควรเก็บ secret เอกสารลับ หรือข้อมูลส่วนบุคคล อย่าให้ AI ตัดสินระดับจากข้อความกำกวม งานที่มีผลภายนอก ค่าใช้จ่าย หรือข้อมูลสำคัญต้องมี Human Approval Gate

ฟีเจอร์และคำสั่งของ OpenClaw หรือ Telegram อาจเปลี่ยนได้ ข้อมูลเชิงผลิตภัณฑ์ในบทความนี้ตรวจจากเอกสารทางการเมื่อ 9 สิงหาคม 2026: OpenClaw Automations (https://docs.openclaw.ai/automation/cron-jobs), OpenClaw Telegram Channel (https://docs.openclaw.ai/channels/telegram) และ Telegram Bots FAQ (https://core.telegram.org/bots/faq) โปรดตรวจเอกสารล่าสุดก่อนนำตัวอย่างไปใช้กับระบบจริง

## ก้าวแรกที่ทำได้วันนี้

เลือก Automation ที่ส่งบ่อยที่สุด เปิดประวัติเจ็ดวัน แล้วนับว่าข้อความใดทำให้ผู้รับลงมือจริง กรอก Notification Contract เพิ่มระดับ Quiet Hours และกุญแจกันซ้ำ จากนั้นทดลองด้วยข้อมูลจำลอง หากข้อความลดลงโดยเรื่องสำคัญไม่ช้าลง ระบบก็เริ่มเป็นผู้ช่วยแทนเสียงรบกวน
