# “คำสั่งลัด” ChatGPT/Codex ใช้อย่างไรให้ได้ผลจริง พร้อมตัวอย่างคัดลอกใช้ได้

หลายโพสต์บนโซเชียลรวบรวมคำอย่าง `/human`, `/expert`, `/viral`, `/brief`, `/translate` และ `/debug` แล้วเรียกว่า “คำสั่งลัด ChatGPT” คำเหล่านี้พิมพ์แล้วอาจได้คำตอบตามต้องการ แต่ต้องเข้าใจให้ถูกว่า **ส่วนใหญ่เป็นเพียงป้ายกำกับ Prompt ที่ผู้ใช้กำหนดเอง ไม่ใช่โหมดลับหรือคำสั่งระบบอย่างเป็นทางการ**

โมเดลทำตามได้เพราะตีความคำภาษาอังกฤษและรายละเอียดที่ตามมา ดังนั้นการพิมพ์ `/viral` อย่างเดียวไม่ได้รับประกันยอดวิว และ `/expert` ก็ไม่ได้ทำให้ข้อมูลถูกต้องขึ้นโดยอัตโนมัติ

## แยกให้ออก: เมนูจริง กับ Prompt label

**เมนูหรือเครื่องมือจริง** คือรายการที่ ChatGPT แสดงให้เลือกในหน้าจอ เช่น Search สำหรับค้นเว็บ และ Study สำหรับช่วยเรียนรู้แบบโต้ตอบ รายการและวิธีเปิดอาจต่างกันตามอุปกรณ์ เวอร์ชันแอป บัญชี และพื้นที่ใช้งาน

**Prompt label** คือคำย่อที่เราตั้งขึ้นเอง เช่น `/brief` หรือ `/human` หากไม่มีรายการให้เลือกจากเมนู ระบบจะอ่านข้อความนั้นเป็นส่วนหนึ่งของ Prompt ธรรมดา

กฎง่าย ๆ: ถ้าพิมพ์ `/` แล้วมีเมนูให้เลือก นั่นอาจเป็นเครื่องมือของหน้าจอที่ใช้อยู่ แต่ถ้าพิมพ์คำแล้วส่งเป็นข้อความทันที ให้ถือว่าเป็น Prompt จนกว่าจะมีเอกสารทางการยืนยัน

## สูตร Prompt 5 ส่วน

ผลลัพธ์ที่สม่ำเสมอกว่าการใช้ slash เดี่ยว ๆ มาจากการระบุ:

1. **บทบาท** — ให้ AI ทำหน้าที่เป็นใคร
2. **เป้าหมาย** — ต้องการให้ทำอะไร
3. **บริบท** — กลุ่มผู้อ่าน ข้อมูลต้นทาง และข้อจำกัด
4. **รูปแบบ** — ภาษา ความยาว ตาราง หรือจำนวนข้อ
5. **เกณฑ์ตรวจ** — สิ่งที่ต้องรักษา สิ่งที่ห้ามแต่ง และวิธีตรวจความถูกต้อง

แม่แบบคัดลอกใช้ได้:

> บทบาท: คุณเป็น [บทบาท]\
> งาน: [ผลลัพธ์ที่ต้องการ]\
> บริบท: [ข้อมูลต้นทาง/กลุ่มเป้าหมาย]\
> รูปแบบ: [ภาษา ความยาว โครงสร้าง]\
> เกณฑ์ตรวจ: [ข้อเท็จจริงที่ต้องรักษา สิ่งที่ห้าม และวิธีตรวจ]\
> ข้อมูล: [วางข้อมูล]

## 10 ตัวอย่างใช้งานจริง

### 1. /brief — สรุปสำหรับผู้บริหาร

ไม่พอ: `/brief สรุปให้หน่อย`

แนะนำ:

> /brief สรุปรายงานด้านล่างเป็นภาษาไทย 5 bullet สำหรับผู้บริหาร เก็บตัวเลข วันที่ ความเสี่ยง และผู้รับผิดชอบให้ครบ หากต้นฉบับไม่ระบุให้เขียนว่า “ไม่ระบุ” ห้ามเดาเพิ่ม

### 2. /human — ปรับภาษาให้เป็นธรรมชาติ

ไม่พอ: `/human เขียนให้เหมือนคน`

แนะนำ:

> /human ปรับข้อความนี้ให้เป็นภาษาไทยธรรมชาติ สุภาพแบบเพื่อนร่วมงานระดับมืออาชีพ ไม่ใช้ถ้อยคำขายฝัน ไม่เพิ่มข้อเท็จจริง และคงความยาวไม่เกิน 120 คำ

คำสั่งนี้ไม่รับประกันว่าจะ “ผ่าน AI detector” และไม่ควรใช้เพื่อหลบเลี่ยงการตรวจสอบ

### 3. /expert — ขอคำอธิบายเชิงผู้เชี่ยวชาญ

> /expert อธิบายความเสี่ยงของการลงทุนแบบถัวเฉลี่ยต้นทุนสำหรับผู้เริ่มต้น แยกข้อดี ข้อจำกัด และสถานการณ์ที่ไม่เหมาะ ใช้แหล่งข้อมูลปฐมภูมิที่เป็นปัจจุบัน พร้อมระบุส่วนที่ยังไม่แน่นอน

ควรขอหลักฐานและตรวจแหล่งอ้างอิงเสมอ เพราะคำว่า expert ไม่เพิ่มความถูกต้องโดยตัวมันเอง

### 4. /translate — แปลโดยรักษาน้ำเสียง

> /translate แปลอีเมลด้านล่างจากไทยเป็นอังกฤษธุรกิจระดับ B1–B2 ให้สุภาพและเป็นธรรมชาติ รักษาชื่อ ตัวเลข วันที่ และเงื่อนไขเดิม จากนั้นอธิบายคำที่เลือกใช้ 3 จุด

### 5. /table — เปลี่ยนข้อมูลเป็นตาราง

> /table แปลงข้อมูลด้านล่างเป็นตารางคอลัมน์ งาน / ผู้รับผิดชอบ / กำหนดส่ง / สถานะ / คำถามที่ต้องยืนยัน หากไม่มีข้อมูลให้ใส่ “ไม่ระบุ” ห้ามสร้างชื่อหรือวันที่ขึ้นเอง

### 6. /email — ร่างอีเมลธุรกิจ

> /email ร่างอีเมลภาษาอังกฤษถึงลูกค้าเพื่อแจ้งว่างานล่าช้า 2 วัน น้ำเสียงรับผิดชอบและสุภาพ มี Subject, คำทักทาย, เหตุผลสั้น ๆ, วันส่งใหม่ และคำขอโทษ ไม่โทษบุคคลอื่น ความยาวไม่เกิน 130 คำ

### 7. /viral — วางคอนเทนต์ที่มีโอกาสดึงความสนใจ

> /viral สร้าง 5 Hook สำหรับ Reel 20 วินาที เรื่อง “AI ช่วยเตรียมประชุม” กลุ่มเป้าหมายคือคนทำงานไทย เปิดด้วยปัญหาใน 2 วินาที หลีกเลี่ยง clickbait และคำรับประกันผลลัพธ์ พร้อมเสนอ CTA แบบไม่ขายแข็ง

`/viral` เป็นเพียงเจตนา ไม่รับประกันยอดเข้าถึง ควรทดสอบด้วย retention, watch time, share, save และ click-through

### 8. /research — ค้นคว้าโดยมีหลักฐาน

> /research ศึกษาหัวข้อนี้จากแหล่งทางการหรือเอกสารต้นฉบับที่อัปเดตล่าสุด เปรียบเทียบอย่างน้อย 2 แหล่ง ระบุวันที่ของข้อมูล แยกข้อเท็จจริงออกจากข้อสรุป และแนบลิงก์ที่รองรับแต่ละประเด็น ห้ามแต่งแหล่งอ้างอิง

### 9. /code — สร้างโค้ดที่ตรวจสอบได้

> /code เขียนฟังก์ชัน JavaScript สำหรับตรวจรูปแบบอีเมล ใช้ Node.js 22 ห้ามเพิ่ม dependency ส่งโค้ดพร้อม test cases สำหรับ input ปกติ ค่าว่าง และกรณีผิดรูปแบบ แล้วอธิบายข้อจำกัดสั้น ๆ

### 10. /debug — วิเคราะห์ข้อผิดพลาด

> /debug วิเคราะห์ error log ด้านล่างในโปรเจกต์ Node.js 22 ระบุสาเหตุที่เป็นไปได้เรียงตามหลักฐาน เสนอวิธีตรวจยืนยันก่อนแก้ และให้ patch ที่เล็กที่สุด พร้อมคำสั่งทดสอบ ห้ามเปลี่ยน dependency โดยไม่แจ้ง

## ตัวอย่างงานครบวงจร: จากบันทึกประชุมเป็น Action Plan

**ข้อมูลต้นทาง**

> ฝ่ายเนื้อหาจะส่งร่างวันศุกร์ ฝ่ายกฎหมายขอตรวจสามวันทำการ แต่ที่ประชุมยังไม่เลือกวันเผยแพร่

**Prompt**

> /table เปลี่ยนบันทึกนี้เป็น Action Plan โดยใช้คอลัมน์ งาน / เจ้าของงาน / กำหนดเวลา / สถานะ / ประเด็นค้าง ใช้เฉพาะข้อมูลที่ระบุ หากไม่มีวันที่หรือชื่อบุคคลให้เขียนว่า “ไม่ระบุ” ห้ามคำนวณวันเผยแพร่แทนทีม

**ผลลัพธ์ที่ควรได้**

| งาน | เจ้าของงาน | กำหนดเวลา | สถานะ | ประเด็นค้าง |
|---|---|---|---|---|
| ส่งร่าง | ฝ่ายเนื้อหา | วันศุกร์ | วางแผนแล้ว | วันที่จริงไม่ระบุ |
| ตรวจร่าง | ฝ่ายกฎหมาย | 3 วันทำการหลังได้รับร่าง | รอดำเนินการ | วันเริ่มขึ้นกับวันที่ได้รับร่าง |
| เผยแพร่ | ไม่ระบุ | ไม่ระบุ | ยังไม่ตัดสินใจ | ต้องเลือกวันเผยแพร่ |

## ผลทดสอบในระบบ OpenAI/Codex

ได้ทดลองส่ง `/brief`, `/translate`, `/table` และ `/human` พร้อมรายละเอียดงานใน Codex ซึ่งใช้ provider OpenAI ผลคือระบบทำตามความหมายของงานได้ แต่คำเหล่านี้ถูกตีความเป็นข้อความ Prompt ธรรมดา ไม่ใช่คำสั่งระบบ การทดสอบจึงยืนยันว่าใช้เป็น **mnemonic ส่วนตัว** ได้ แต่ควรเขียนรายละเอียดต่อท้ายทุกครั้ง

## Checklist ก่อนกดส่ง

- ระบุว่าต้องการผลลัพธ์อะไรและให้ใครอ่าน
- แนบข้อมูลต้นทางที่จำเป็น
- กำหนดภาษา ความยาว และโครงสร้าง
- บอกสิ่งที่ห้ามเดาหรือห้ามเปลี่ยน
- งานข้อมูลปัจจุบันให้ขอค้นเว็บและลิงก์แหล่งอ้างอิง
- งานโค้ดให้ระบุ environment, error log และคำสั่งทดสอบ
- งานที่มีผลภายนอก เช่น ส่งอีเมล เผยแพร่ แก้ไฟล์ หรือทำธุรกรรม ให้ตรวจและอนุมัติก่อน

## สรุป

slash prompt มีประโยชน์ในฐานะคำจำง่าย แต่คุณภาพไม่ได้มาจากเครื่องหมาย `/` คุณภาพมาจากบริบท รูปแบบ และเกณฑ์ตรวจที่ชัดเจน ใช้คำลัดได้ แต่อย่าให้คำลัดแทนรายละเอียดที่ AI ต้องรู้
